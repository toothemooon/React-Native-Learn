## 2024-05-01 - Accessible Icon Buttons and Touch Targets
**Learning:** In React Native, `Pressable` components that only contain icons (like back buttons, settings gears, etc.) are completely opaque to screen readers by default. Screen reader users will simply hear "button" (if lucky) or just nothing. Furthermore, small icons without a `hitSlop` present a physical accessibility challenge for users with motor impairments or fat-finger errors on mobile devices.
**Action:** Always add `accessibilityRole="button"` and a descriptive `accessibilityLabel` to icon-only `Pressable` components. Always provide a generous `hitSlop` (e.g., `hitSlop={{ top: 10, bottom: 10, left: 10, right: 10 }}`) to expand the touch target area without affecting the visual layout.
## 2026-10-04 - React Native Pressable Accessibility States and Tactile Feedback
**Learning:** By default, React Native `Pressable` components mapped over lists do not announce their selection state to screen readers, and they lack native visual feedback. Relying solely on external style arrays for 'active' state isn't enough for true accessibility.
**Action:** When rendering lists of selectable items (like cards) using `Pressable`, always include `accessibilityRole="button"` and `accessibilityState={{ selected: boolean }}` alongside descriptive `accessibilityLabel`s. Simultaneously, implement tactile feedback by passing a function to the `style` prop (e.g., `style={({ pressed }) => [...]}`) to dynamically adjust opacity and scale, ensuring both visual and auditory users receive clear interaction cues.
